01

From a Toy Model to a Deployed LLM

Templeton, Conerly, Marcus, Batson et al. — Anthropic — May 2024 Transformer Circuits transformer-circuits.pub

The problem

Presentation 04 (Towards Monosemanticity) proved you could decompose a model's activations into clean, interpretable features using a sparse autoencoder — but it did so on a one-layer toy transformer. The open question was the only one that matters for safety: does this technique survive contact with a model people actually use? Production models are deeper, wider, trained on far more data, and saturated with the messy abstractions of real language.

The contribution

This paper takes the same recipe and applies it to Claude 3 Sonnet — a mid-size frontier model in production. Rather than try to decompose the whole network, they attach a sparse autoencoder to a single point in the middle of the model: the residual stream halfway through. The residual stream is a good target because it is relatively small (a bottleneck every layer reads from and writes to) yet carries the model's working representation of the input.

The SAE reads the residual-stream activation vector and re-expresses it as a sparse combination of a large dictionary of learned feature directions: of the millions of features available, only a handful are active on any given token. Each active direction turns out to correspond to a human-recognisable concept.

The mechanism

The residual stream of dimension d is far smaller than the number of concepts a model represents, so concepts are packed in superposition (Presentation 03). The SAE's job is to un-pack that superposition: project the dense activation onto an over-complete dictionary so each axis means one thing. Crucially, nothing about the recipe is toy-specific — it transfers straight to a frontier model.

02

Three SAEs — and SAEs Themselves Scale

The contribution

To probe how dictionary size affects what you can find, they trained three sparse autoencoders of increasing width on the same residual-stream activations, with roughly 1 million, 4 million, and 34 million features. The recurring lesson of the deep-learning era reappears here: SAE training itself follows clean scaling laws. Reconstruction loss falls predictably as a power law in the amount of compute and the number of features, which let the team choose hyperparameters for the big runs by extrapolating from cheap small ones — exactly the Kaplan/Chinchilla playbook, now applied to interpretability tooling.

Even 34M is not enough

The dictionaries are large, but the paper is candid that they are incomplete. Even the 34M-feature SAE fails to capture everything the model represents: many concepts appear only in the larger run (rare concepts need a bigger dictionary to earn a dedicated feature), and a fraction of features are "dead" — they never activate on the training data and waste capacity. The team estimates the full set of features in Sonnet could be orders of magnitude larger still.

Why it matters

Two engineering takeaways. First, your interpretability budget behaves like a model-training budget — spend it with scaling laws, not hunches. Second, feature dictionaries are a lossy, capacity-limited view: more features reveal rarer concepts, so "we didn't find a feature for X" never means "the model has no representation of X."

03

Features Are Abstract, Multilingual, Multimodal

The contribution

Unlike the toy model's mostly lexical features, Sonnet's features are genuinely conceptual. A single feature tracks a concept regardless of how it is expressed:

  • Multilingual. A feature for a concept fires on text discussing that concept in English, French, Chinese, and other languages alike — it tracks meaning, not surface tokens.
  • Multimodal. The same feature that fires on text about a concept also fires when Sonnet is shown an image of it. (Sonnet is a vision-capable model.) A feature is a representation of the concept, not of the wordform.
  • Concrete and abstract. A feature can respond both to direct mentions of an entity and to abstract discussion around it — e.g. a feature for a famous person, a feature for the Golden Gate Bridge, or abstract features such as "inner conflict," code with bugs, or rhetorical devices like sarcasm.

The insight

This is direct evidence that frontier models build language- and modality-independent concepts — the long-hypothesised abstract internal representation, now made legible. It also means a single feature is a robust monitoring handle: you watch the concept, not a brittle keyword list.

04

Safety-Relevant Features

The contribution

Because the dictionary spans the model's whole working representation, it includes features for concepts that matter directly for safety and oversight. The paper documents features for, among others:

Code security unsafe

Features for security vulnerabilities and backdoors in code — firing on buffer overflows, injection, and hidden backdoor logic.

Deception & lying unsafe

Features tracking deception, lying, and withholding information — both in described characters and in the model's own framing.

Sycophancy caution

A sycophantic praise feature — the tendency to flatter or tell the user what they want to hear.

Bias & slurs caution

Features for bias, hateful content, and slurs across protected categories.

Power-seeking & danger unsafe

Features related to power-seeking, coups, and dangerous / biohazard content (e.g. bioweapon-adjacent material).

Self-representation notable

Features tied to the model's representation of itself as an AI — firing when it reasons about being an AI assistant.

Caveat

The existence of these features is expected, not alarming. A model trained on human text must represent deception, bias, and danger in order to recognise and discuss them — just as it must represent kindness or chemistry. Their value is as instrumentation: a feature that lights up when the model is being deceptive or sycophantic is a candidate monitor on the model's internals, not evidence the model is dangerous. The point is observability, not indictment.

05

Causality: Clamping & "Golden Gate Claude"

The problem

An interpretable label is only a correlation until you can show the feature does something. Does a feature merely co-occur with a concept, or does it cause the model's behaviour around that concept?

The mechanism

The test is feature steering (or "clamping"): during a forward pass, artificially override a single feature's activation — pin it high or low — while the rest of the model runs normally, and watch the output. Because the SAE gives you a clean direction in the residual stream, you can intervene on exactly one concept at a time.

The famous demonstration: clamp the Golden Gate Bridge feature to a strongly positive value and you get "Golden Gate Claude" — an assistant that steers nearly every conversation, no matter the topic, back to the bridge, even claiming to be the bridge. The same lever works on safety features: clamping a code-vulnerability or deception feature high induces the associated behaviour; clamping it low can suppress it. Behaviour moves predictably and in the direction the feature's label implies.

The insight

Steering converts features from descriptions into causal handles. A feature is not just "what the model was thinking about when it said X" — turning it changes what the model says. That is the difference between a post-hoc explanation and a control surface you could build monitoring and intervention on.

Feature Geometry — a Map of Concepts

The contribution

The dictionary is not an unordered bag of features. When you look at which features sit near each other in the SAE's feature space, the neighbourhoods are semantically coherent: a feature's nearest neighbours are conceptually related to it. The local geometry of the dictionary encodes a map of how the model organises concepts.

The paper also finds feature splitting across SAE sizes: a broad concept that occupies one feature in the 1M dictionary fractures into several finer-grained features in the 34M dictionary — the bigger the dictionary, the finer the conceptual resolution. Geometry and splitting together suggest the feature set is structured, not arbitrary.

The mechanism

Semantic neighbourhoods mean the dictionary is browsable: find one relevant feature and its neighbours surface related ones — useful when assembling a panel of features to monitor a behaviour. Feature splitting is the same scaling-law story at the concept level: more capacity buys finer distinctions, not just more of the same.

07

What to Take Away

  • Interpretability scales to deployed models. The sparse-autoencoder recipe from the toy model works on Claude 3 Sonnet, a real production frontier model — extracting interpretable features from its middle residual stream.
  • Bigger dictionaries, finer concepts. Three SAEs (~1M / 4M / 34M features) were trained, and SAE training itself obeys scaling laws. Even 34M features is incomplete — dead features and missing rare concepts remain.
  • Features are abstract, multilingual, multimodal. One feature tracks a concept across languages, across text and images, and across concrete and abstract mentions — evidence of genuine internal concepts.
  • Safety-relevant features exist — as instruments. Deception, sycophancy, bias, code backdoors, power-seeking, dangerous content, and self-representation all have features. Their existence is expected; their value is monitoring, not alarm.
  • Features are causal, not just descriptive. Clamping a feature steers behaviour predictably — "Golden Gate Claude" is the vivid proof, and safety features can be induced or suppressed the same way.
  • The through-line: superposition (03) said concepts are packed in; SAEs (04) unpacked a toy; this paper unpacks a real model and turns its features into a steering and observability surface.
